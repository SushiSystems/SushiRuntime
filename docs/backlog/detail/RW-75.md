# RW-75 Make the five medium tests quarantined under AdaptiveCpp pass on its CPU backend

The row of this entry is in `docs/backlog/CORRECTNESS.md`. This file holds what did not fit the row.

- State: open

- Source: `cmake/SushiRuntimeTests.cmake`

The Linux adaptivecpp CI job reached the tests for the first time on 2026-10-29, at 9c3d7216, and
these five failed there while every other toolchain passed them. Each has its known issue:

| Issue | Test |
| --- | --- |
| KI-18 | `Medium_UsmAllocatorFailure.LogsTheRefusedRequest` |
| KI-19 | `Medium_PlacementScopeDevice.AKindOrMemoryNoDeviceHasIsAbsent` |
| KI-20 | `Medium_RuntimeSession.ResolvesEverySubmitThreadToAnEnclosingZone` |
| KI-21 | `Medium_InteropBorrow.ARangeCopyReachesBorrowedMemoryTheRuntimeDidNotAllocate` |
| KI-22 | `Medium_MemoryExchangeImport.AKindTheDeviceDoesNotImportIsRefusedByName` |

The causes are not yet known. Each one is a runtime or test that assumes DPC++ behaviour where
AdaptiveCpp's CPU backend behaves differently. The quarantine applies only when
`SR_SYCL_TOOLCHAIN` is `adaptivecpp`.
