# Wave 1, Task 7a: sushiruntime takes sushicore from PyPI

## What was done

- Added `"sushicore>=0.1.0",` to `dependencies` in `cli/pyproject.toml`.
- Deleted the six-line comment block starting `# sushicore (shared CLI presentation layer`
  that explained sushicore could not be declared as a dependency.
- Created `docs/reference/CHANGELOG.md` (did not exist before) with a three-line header
  (`# Changelog`, blank line, `## Unreleased`) matching the format used by sushiai, sushidsp
  and sushitrack, followed by the one-line entry:
  `- 2026-09-22 — Took \`sushicore\` from PyPI instead of a sibling checkout (\`cli/pyproject.toml\`).`
- Verified the install and test suite from a clean throwaway virtual environment, then deleted
  it.

## What was not done

- No commit was made (per instructions, the orchestrator commits).
- `.venv-check` needed `pytest` installed separately to run the suite — it is not declared as a
  dependency or extra anywhere in `cli/pyproject.toml` (no `[project.optional-dependencies]`
  section exists in this repository). This is expected for a test runner, not a defect; noted
  here since the plan didn't call it out.
